# 架构与开发维护

站点继续以 VitePress 生成静态 HTML。文档数据在构建阶段整理，阅读统计和反馈由同源 Pages Functions 提供，旧统计 Worker 保留兼容入口，排行 Worker 单独展示统计结果。

## 文档与搜索

文档目录统一保留源文件路径、公开地址、标题、摘要、标签、作者、置顶顺序、页面类型及更新时间。标签路由、首页推荐、最近更新、排行和文档检查都使用这份目录，元数据使用标准 YAML 解析。新增元数据规则应修改共享数据层，并补边界测试，避免单独在组件里解析。

公开地址仍按现有文件名生成，支持普通子目录及子目录首页。页面分类规则位于共享数据层；新增功能页应同时决定它是否参与搜索、统计和推荐。标签名生成的地址不能冲突。

本地搜索在构建和浏览器中使用相同的中文分词。中文短词不启用模糊匹配，英文保留前缀和拼写容错。反馈功能页和明确声明不收录的页面不进入正文搜索。搜索分词函数会被 VitePress 序列化，必须能够脱离模块上下文独立执行。

反馈组件随相应页面加载，首页卡片和推荐数据随首页加载。修改加载方式时，应同时检查浏览器依赖和预渲染 HTML，保留无脚本反馈表单。

## 本地开发

统一使用 Node.js 24 和仓库中的 npm 锁文件：

```sh
npm ci
npm run dev
```

快速开发只运行文档站。需要接口时使用：

```sh
npm run dev:full
```

该命令检查端口、初始化并迁移本地 D1，启动 Pages Functions，再启动带热更新的 VitePress。浏览器访问 `http://127.0.0.1:5173`；同源 `/api` 请求代理到本机 `8788` 端口。首次缺少静态产物时会先构建。退出时关闭本次启动的子进程。

可以通过 `DOCS_API_PORT` 和 `DOCS_WEB_PORT` 调整端口。把 `.dev.vars.example` 复制成 `.dev.vars` 可配置本地审计口令；两者都未配置时使用工具提示的本地默认口令。本地 Pages 和迁移命令使用本地数据库，生产数据库标识不会导致本地命令访问线上。

根级 Wrangler 配置管理非敏感的 Pages 绑定。生产口令仍存放在 Cloudflare Secrets 中。远端 Preview 默认不绑定生产数据库；启用完整远端预览前，应创建独立 D1 库，在预览环境配置绑定与口令，并对该库执行迁移。

## 数据库和提交约定

数据库升级由显式迁移命令执行，在线请求不创建表或修改列。已有库的首次接管会检查实际结构，只补充缺少的部分，并保留已有数据。迁移版本与校验值会写入版本表；已应用的迁移应保持不变，后续升级新增版本。

反馈提交使用稳定请求标识。相同标识和相同内容会返回原查询码；相同标识配不同内容会拒绝，避免覆盖旧反馈。自动重试和恢复待发内容必须保留标识；用户修改内容后才创建新提交。旧客户端及无脚本表单仍可提交。

旧统计 Worker 与 Pages 入口共用统计实现，累计阅读和每日阅读在同一批数据库操作中更新。撤除旧入口前应确认实际调用情况。

## 验证与发布

```sh
npm test                 # 文档、搜索、接口、迁移与检查器回归
npm run build            # 源码检查、构建、产物链接和搜索验证
npm run test:local       # 独立本地数据库中的真实 Pages 集成检查
npm run verify           # 完整验证及排行清单生成
```

本地集成检查会建立独立临时数据库，验证预渲染表单、鉴权、阅读统计、原生提交和反馈重试，结束后清理本次测试数据。

PR 和生产发布复用同一验证工作流。生产流程下载经过验证的静态产物和排行清单，确认提交仍是 main 最新版本，再依次执行兼容迁移、Pages 发布、旧统计 Worker 发布和排行发布。生产流程串行执行；迁移或任一发布步骤失败会停止后续步骤。

所有 Wrangler 命令使用 npm 锁文件中的本地版本。生产部署 token 需要 Pages、Workers 和 D1 的相应编辑权限；D1 权限用于发布前迁移。迁移执行失败时不会继续发布新接口。

本轮的进度与验证结果见[架构改进计划](architecture-plan.md)。
